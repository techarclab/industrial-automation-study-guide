Rule 1

GPIO pins are 3.3 V only

Never connect a 5 V, 12 V or 24 V signal directly to an ESP32-C3 pin. The pins are not 5 V tolerant.

Rule 2

Field signals need an interface

Plant signals are usually 24 V DC. An opto-isolator, input module or level shifter always sits between them and the microcontroller.

Rule 3

Wire, check, then power

Wire with USB unplugged, have the wiring checked, then connect power. Most lab damage happens in the first second.

1.1

What is an embedded system?

You will learn
  • The definition, and how an embedded system differs from a PC
  • The sense → process → act block diagram
  • How embedded systems are classified, and where they are used

An embedded system is a computer built into a larger product to do one specific job, usually with fixed hardware, limited resources and a timing requirement. The user sees the product (a washing machine, an energy meter, a motor drive), not the computer inside it.

A sensor turns a physical quantity (heat, light, humidity) into an electrical signal. The input interface makes that signal safe and readable for the MCU. The MCU runs the firmware and decides what to do. The output interface drives an actuator such as a relay or buzzer. Communication sends data to other devices or the cloud, and the watchdog resets the system if the firmware hangs.

Key idea · hard vs soft real-time

In a hard real-time system, a missed deadline is a failure (airbag, motor over-current trip). In a soft real-time system, a late result is worse but still useful (a dashboard that refreshes a little late). Real-time means predictable, not necessarily fast.

Processor architectures

You will learn

One-line answer for the exam

A microprocessor needs external memory and peripherals to work. A microcontroller has them inside the chip.

Von Neumann vs Harvard

Most modern MCUs, including the ESP32-C3, use a modified Harvard design: separate instruction and data paths inside the chip for speed, but one unified address map so the programmer sees a single memory space.

Common mistake
  • Writing a sensor value to the same flash location every second will wear that sector out within days to months. Firmware uses wear-levelling to spread writes across many sectors.
  • The ESP32-C3 has no real EEPROM. The Arduino EEPROM library only emulates it in flash. Use Preferences (NVS), which does wear-levelling for you.

1.4

On-board interfaces: UART, I2C and SPI

You will learn
  • How to wire each bus
  • What a UART frame and an I2C transaction look like on the wire
  • How to choose between them

These three buses connect the MCU to other chips on the same board, or a short cable away: centimetres, not metres. Long industrial cables use RS-485 or Ethernet instead (1.5).

UART

  • Two data wires: TX of one device goes to RX of the other, and GND is shared.
  • Asynchronous: there is no clock wire, so both sides must agree on the baud rate (bits per second) in advance.
  • “115200 8N1” means 115,200 bit/s, 8 data bits, no parity, 1 stop bit. Each byte therefore costs 10 bits on the wire.
  • Used for the debug console (Serial Monitor), GPS modules and cellular modems, and it is the base for RS-232 and RS-485.

I2C

  • Two wires shared by all devices: SDA (data) and SCL (clock). The master drives the clock, so I2C is synchronous.
  • Every slave has an address, usually 7 bits. The master sends it first and only the matching device answers with an ACK.
  • The lines are open-drain: devices can only pull them LOW. Pull-up resistors (typically 4.7 kΩ) pull them HIGH. Missing pull-ups are the most common I2C fault.
  • Speeds: 100 kbit/s (Standard), 400 kbit/s (Fast), 1 Mbit/s (Fast-mode Plus).

SPI

  • Four wires: SCLK (clock), MOSI (master out, slave in), MISO (master in, slave out) and CS (chip select, active LOW), with one CS per slave.
  • Full-duplex: data moves in both directions on every clock pulse.
  • No addresses: the master picks a slave by pulling its CS LOW.
  • Fast, typically 1–80 MHz. Four modes (0–3) set clock polarity and phase; master and slave must use the same mode.
  • Used for flash memory, SD cards, TFT displays, fast ADCs and Ethernet controllers.

1.5

External interfaces

You will learn
  • Why differential signalling survives factory noise
  • RS-232, RS-485, Ethernet, USB, Bluetooth and Wi-Fi compared
  • Why a transceiver chip is always needed between the MCU and the cable

External interfaces connect the device to other machines, a PC or a network. Distance and electrical noise now matter much more than on the board.

Single-ended vs differential

Single-ended links (UART, RS-232) measure the signal between one wire and ground, so any noise picked up by the wire changes the signal. Differential links (RS-485, CAN, Ethernet, USB) use a twisted pair and measure the difference A − B. Noise hits both wires almost equally and cancels out.

Danger

RS-232 (up to ±15 V) and RS-485 levels are not logic levels. The ESP32-C3 UART connects to them only through a transceiver: MAX3232 for RS-232 and MAX3485 for RS-485 (both 3.3 V parts; the common MAX485 is a 5 V part). RS-232 wired straight to a GPIO will destroy it.

RS-485 wiring rules
  • Twisted-pair cable, nodes daisy-chained (never star-wired)
  • 120 Ω termination at each far end only
  • Bias resistors once per bus, so the line is in a known state when nobody transmits
1.6

PCB fundamentals

You will learn
  • PCB vocabulary and the 4-layer stack-up
  • Layout rules that keep a board reliable in a noisy plant
  • The basics of signal integrity and thermal management

A PCB is more than wires on fibreglass. Its layout decides whether a product runs for years in a factory or resets every time a motor starts.

TermMeaning
SubstrateThe board material, usually FR-4 (glass-fibre epoxy)
LayerA copper sheet. Simple boards have 2; boards with MCUs and radios usually have 4 or more
TraceA copper “wire” on a layer
ViaA plated hole that connects traces on different layers
PlaneA large copper area used for ground or a supply voltage
Pad / footprintThe copper shape a component is soldered to
Solder maskThe coloured coating that stops solder bridges
SilkscreenPrinted labels such as R1, U3 and pin-1 marks

Layout rules: place by function first

  1. Group by function as in Fig 1.10: switching regulators and relays away from ADC inputs, the crystal and the antenna.
  2. Decoupling capacitors (typically 100 nF) as close as possible to every IC power pin, with a short via to ground. They supply the fast current bursts the chip draws.
  3. Trace width follows current. Signal traces can be thin; power traces must be wide enough not to overheat (use an IPC-2152 calculator).
  4. Clearance and creepage between high-voltage and low-voltage copper, for example 230 V or 24 V field wiring vs 3.3 V logic. Safety standards set the minimum distances.
  5. Antenna keep-out: no copper, ground or parts under or near the Wi-Fi/BLE antenna.

Signal integrity

Signal integrity means the signal that arrives still looks like the one that was sent.

  • Every current returns to its source. At high frequency the return current flows in the ground plane directly under the trace. A slot in the plane forces a long detour, which radiates noise and causes crosstalk.
  • Keep fast traces short and route them over a solid plane.
  • Crosstalk: parallel traces couple into each other. Add spacing, or a ground trace between them.
  • Controlled impedance (for example 50 Ω for RF, 90 Ω differential for USB) stops fast signals reflecting.

Thermal management

  • Heat comes mainly from regulators, power transistors, relay coils, and the radio when it transmits.
  • Use copper pours and thermal vias under hot parts to spread heat into the inner layers.
  • Use a switching regulator instead of a linear one when the voltage drop is large (see 2.3).
  • Derate parts: an industrial product must work at the top of its temperature range inside a closed panel, not at room temperature on a lab bench.

From idea to board

  1. Schematic capture and component selection
  2. Footprint assignment and design-rule setup (clearances, trace widths)
  3. Placement by function, then routing
  4. Design Rule Check (DRC) and review
  5. Export Gerber and drill files; fabrication
  6. Assembly, then bring-up (1.7)
1.7

Bootloaders and system bring-up

You will learn
  • What happens between power-on and setup()
  • U-Boot, secure boot and the chain of trust
  • Partition layouts and safe over-the-air (OTA) updates

A bootloader is a small program that runs first after power-on or reset. It initialises the minimum hardware, chooses which firmware to run, optionally checks that the firmware is genuine, then jumps to it. It also lets new firmware be loaded over USB, UART or the air.

  1. Power-on / reset: the CPU starts executing from a fixed address in internal ROM.
  2. ROM bootloader: burned in at the factory and cannot be changed. It samples the strapping pins (GPIO2, GPIO8, GPIO9 on the ESP32-C3). GPIO9 LOW enters download mode.
  3. Second-stage bootloader: stored in flash. It reads the partition table and decides which application slot to run.
  4. Application: your firmware.

U-Boot is the common second-stage bootloader on Linux-class processors (Raspberry Pi-type SoCs, industrial gateways). It initialises DRAM, loads the Linux kernel, device tree and root file system from eMMC, SD or the network, then starts Linux. MCUs such as the ESP32 use their own vendor bootloader instead.

System bring-up

Bring-up is powering a new board for the first time and proving each part works, one step at a time.

Two safety nets every product needs
  • Watchdog timer: a hardware timer the firmware must reset regularly. If the code hangs, the watchdog expires and resets the chip.
  • Brown-out detector: resets the chip cleanly when the supply dips too low, instead of letting it run and corrupt flash.

Secure boot: the chain of trust

Without secure boot, anyone with physical access can flash malicious firmware. Secure boot builds a chain of trust that starts in hardware that cannot be changed.

  • The manufacturer signs firmware with a private key kept secret on a build server.
  • The device stores only a hash of the matching public key in one-time-programmable eFuses.
  • Secure boot is normally combined with flash encryption, so the firmware cannot be read out and cloned.
Warning

Enabling secure boot or flash encryption permanently burns eFuses. Done wrongly, the board can never be reflashed. Never enable them on lab boards.

2.1

Industrial digital I/O

You will learn
  • 24 V logic levels and why they are used
  • Sinking vs sourcing (NPN vs PNP)
  • Relays, SSRs, flyback diodes and opto-isolation
  • Fail-safe outputs, interrupts and debouncing for Lab 1

In a factory, digital signals run at 24 V DC, not 3.3 V or 5 V. The higher voltage gives a large margin against noise and against voltage drop on long cables.

Sinking vs sourcing (NPN vs PNP)

These words describe which side of the load the switch is on.

  • A sourcing device supplies current: it switches +24 V to the load. A PNP sensor output is sourcing.
  • A sinking device receives current and passes it to 0 V: it switches the load to 0 V. An NPN sensor output is sinking.

PNP is the usual choice in modern plants in Europe and India; NPN is common on Japanese and other Asian machines. Always check the input module's datasheet before buying sensors.

A relay has COM (common), NO (normally open: connected to COM only when the coil is energised) and NC (normally closed: connected to COM when the coil is off) terminals.

Why the flyback diode matters

A coil is an inductor. When the transistor switches off, the coil tries to keep current flowing and produces a voltage spike of tens to hundreds of volts, which destroys the transistor. The diode gives that current a safe path. For AC coils and contacts, use an RC snubber or varistor instead.

Isolation

Field wiring runs through the plant past motors and welders and can carry spikes of hundreds of volts. It must never share a ground with the MCU. An optocoupler passes the signal as light across a gap, so the two sides have no electrical connection.

Fail-safe output design

An alarm or safety output should go to its safe state when anything fails, including a cut wire or a dead power supply. That is why industrial alarm relays are normally energised.

SituationNormally de-energised (unsafe)Normally energised (fail-safe)
HealthyRelay offRelay on
AlarmRelay on → alarmRelay off → alarm

Reading inputs: polling, interrupts and debouncing

Polling checks the pin in loop(); a short pulse can be missed while the code is busy. An interrupt makes the hardware call a function (an ISR) the instant the pin changes. Keep an ISR tiny: set a flag or timestamp and do the real work in loop().

Mechanical contacts bounce, and comparator-based sensor modules chatter when the signal is near their threshold. One event can produce many edges. Debouncing ignores changes until the signal has been stable for a set time.

In the lab (Lab 1)

The IR and flame modules run from 3.3 V, so they connect directly to the ESP32-C3. Power them from 3.3 V, not 5 V: at 5 V their output pin also swings to 5 V and can damage the GPIO.

2.2

Analog signals: 4–20 mA and 0–10 V

You will learn
  • How a 4–20 mA current loop works and why it starts at 4 mA
  • Converting current to engineering units
  • NAMUR NE43 fault ranges and loop fault-finding

Transmitters for pressure, level, flow and temperature send a continuous value rather than ON/OFF. Two standards dominate: the 4–20 mA current loop and the 0–10 V voltage signal.

Why current, not voltage?

In a series loop the current is identical at every point (Kirchhoff's current law). Cable resistance drops voltage, but not current, so the receiver reads the right value over hundreds of metres. Current loops also pick up far less noise than voltage signals.

Why start at 4 mA? The “live zero”

  1. Broken-wire detection: 0 mA can only mean a fault. With 0–20 mA you could not tell “0 %” from “cable cut”.
  2. Powering the sensor: a 2-wire transmitter runs its electronics from the loop current itself. The 4 mA minimum is enough to power it.
Worked examplecurrent → pressure

A 0–10 bar pressure transmitter reads 12 mA. What is the pressure?

Value = (I − 4) ÷ 16 × (max − min) + min = (12 − 4) ÷ 16 × 10 = 5 bar

Loop types. 2-wire transmitters are loop-powered and most common. 3-wire and 4-wire types have separate supply wires, for sensors that need more power. Many transmitters also support HART, which superimposes a digital signal on the 4–20 mA loop for configuration and diagnostics.

0–10 V signals

  • 0 V = 0 %, 10 V = 100 %, usually over 3 wires (supply, signal, ground).
  • Weaknesses: cable voltage drop gives a wrong reading, noise changes the value directly, and a broken wire reads 0 V, which looks like a valid 0 %.
  • Fine for short runs inside a panel, such as a speed reference to a VFD. Use 4–20 mA for long field runs.
  • The ESP32 ADC cannot take 10 V: use a resistor divider, ideally buffered.

2.3

Power supply modules

You will learn
  • Linear regulator vs SMPS, with the efficiency maths
  • How to choose and size a DIN-rail PSU
  • How redundant supplies are built

Power problems cause more field failures than software bugs. An industrial device must survive brown-outs, spikes and years at high temperature.

Linear regulator vs switch-mode supply

A linear regulator (LM7805, AMS1117-3.3) behaves like a variable resistor: it drops the extra voltage and burns it as heat. An SMPS switches a transistor fully on and off thousands of times per second and smooths the result with inductors and capacitors. A switch that is fully on or fully off wastes very little power.

Linear loss = (Vin − Vout) × I. SMPS loss = Pout ÷ efficiency − Pout. Quiescent current is ignored.

A common pattern is a buck SMPS from 24 V down to about 5 V, then a low-noise LDO (low-dropout linear regulator) from 5 V to 3.3 V for the MCU and analog parts. The small 5 V → 3.3 V drop keeps the LDO's loss low.

DIN-rail power supplies

  • Wide AC input range, and a DC-OK relay contact that the controller can monitor.
  • Adjustable output (for example 24–28 V) to compensate for cable drop.
  • Derating curve: full rated power only up to a stated temperature, often around 55–60 °C; above that, available power falls.
  • Overload behaviour (constant current or hiccup mode) and short-circuit protection.
  • Sizing: add up every load, include the inrush current of relays and solenoids, then add margin (commonly 20–30 %).

Redundancy

Mandatory

Each PSU must carry the full load alone. Never wire two outputs directly together: use a redundancy module.

Mandatory

Monitor each PSU's DC-OK contact. Otherwise one supply fails silently and you find out only when the second one fails.

Optional

Add a DC-UPS (battery or supercapacitor buffer) so the controller can finish writing data and shut down cleanly during short outages.

The key idea: duty cycling

Battery life depends on average current, and the average is set mostly by how long the device stays awake. So: wake briefly, do the work, and sleep as deeply as possible.

Worked examplebattery life

Awake at 80 mA for 3 s every 10 minutes (600 s); asleep at 0.05 mA (50 µA, board level) the rest of the time; 2000 mAh battery.

Average = (80 × 3 + 0.05 × 597) ÷ 600 = (240 + 29.9) ÷ 600 ≈ 0.45 mA
Life ≈ 2000 ÷ 0.45 ≈ 4,450 h ≈ 185 days before derating

The awake part (240) is 8× the sleep part (30). Shortening the awake time (faster Wi-Fi connection, fewer reports) helps more than anything else.

Low-power checklist

  1. Use the deepest sleep mode that meets the requirement.
  2. Report less often; batch several readings into one transmission.
  3. Power sensors from a GPIO or load switch so they are fully off during sleep.

  5. Remove power LEDs and USB-serial chips on production boards.
  6. Measure with a meter or power profiler that captures both µA and 100+ mA peaks.
Deep sleep on the ESP32-C3

2.5

Industrial panel design

You will learn
  • How a control panel is laid out, and why
  • How to size an enclosure and estimate its temperature rise
  • IP ratings, DIN rail, terminal blocks and ferrules

In a plant, electronics live in a control panel that protects them from dust, water and heat, and protects people from them.

230 V AC wiring is kept physically apart from 24 V DC and signal wiring, which reduces both noise and risk.

Sizing an enclosure

  1. List every device with its width on the DIN rail and its height.
  2. Add space for wire ducts (typically 40–60 mm between rows) and cable bending room.
  3. Add spare space, commonly 20–30 %, for future modules.
  4. Check depth: tallest device + door clearance + any door-mounted HMI or switches.

Heat dissipation

Every PSU, relay and controller turns part of its power into heat. In a closed box, the temperature rises until the walls lose heat as fast as it is produced. A first estimate for a painted sheet-steel enclosure in still air:

ΔT = P ÷ (k × A) with k ≈ 5.5 W/(m²·K)
Panel temperature estimateFirst-pass check before choosing cooling
Temperature rise10.9 K
Inside the panel50.9 °C
Within limit: natural cooling is enough

Take the effective area from the enclosure maker's datasheet; walls against a surface do not count. This is a rough estimate, not a substitute for the manufacturer's thermal calculation.

Cooling options, cheapest first: natural convection (bigger box, vents) → filter fan (air in low, out high) → heat exchanger (keeps the box sealed) → panel air conditioner. Mount hot parts high, sensitive parts low, and shade outdoor panels from direct sun.

Ingress Protection (IP) ratings · IEC 60529

IP XY: the first digit X rates protection against solids and dust; the second digit Y rates protection against water.

Typical choices: IP20 for modules inside a panel, IP54 for an indoor factory panel, IP65/IP66 outdoors or where floors are hosed down. A fan or cable gland lowers the panel's real rating unless it carries the same rating itself. Higher is not always “better”: IP67 (immersion) does not imply IP66 (jets) unless both are marked.

DIN rail, terminal blocks and wire management

  • DIN rail (EN 60715): the most common is the 35 mm “top-hat” rail (TS35), 7.5 mm or 15 mm deep. Devices clip on and off without tools.
  • Terminal blocks join panel wiring to field wiring. Types: screw, spring-clamp and push-in (fast and vibration-resistant). Special types: PE (earth) terminals in green-yellow bonded to the rail, fused terminals, disconnect terminals for testing, and multi-level terminals to save space.
  • Wire colours: IEC 60204-1 recommends green-yellow for protective earth, light blue for neutral, black for power, red for AC control and dark blue for DC control. The plant's own standard and drawings always take priority.
  • Labelling: every wire and terminal carries a number that matches the wiring diagram. An unlabelled panel is almost impossible to maintain.

Ferrules

A ferrule is a metal tube crimped onto the end of a stranded wire before it goes into a terminal. Without one, strands splay out (short circuits), break under vibration, or are cut by the terminal screw.

  • Match the ferrule to the wire cross-section; the plastic collar is colour-coded by size.
  • Use a proper ferrule crimping tool, never pliers.
  • Use a twin ferrule when two wires must share one terminal.
  • Pull-test every crimp.

Crimping

A crimp is a cold weld: the terminal is squeezed so hard that strands and terminal become one gas-tight joint. In vibration, a good crimp is more reliable than solder, because soldered stranded wire becomes stiff and breaks where the solder ends.

  1. Match the terminal to the wire size (mm² or AWG) and to the connector family.
  2. Strip to the exact length in the terminal datasheet, with no nicked or cut strands.
  3. Use the correct crimp tool and die. Ratcheting tools do not release until the crimp is complete.
  4. Inspect: strands fully inside the barrel, insulation held by the insulation crimp, no stray strands.
  5. Pull-test every crimp by hand.
Common mistakes

Pliers instead of a crimp tool · wrong die size · tinning the wire end with solder before crimping or clamping · pushing a crimped pin into the wrong position in the housing.

EMC, EMI and compliance

You will learn
  • The source–path–victim model of interference
  • Conducted vs radiated emissions, and practical fixes
  • What CE, FCC, BIS and WPC cover
  • EMI (electromagnetic interference) is unwanted electrical noise that disturbs a circuit.
  • EMC (electromagnetic compatibility) is a device's ability to (1) not emit too much noise and (2) keep working when exposed to noise from others. Both halves are tested.
ConductedRadiated
Travels throughPower cables, signal cables, shared groundAir, as electromagnetic waves
Test range (typical)~150 kHz – 30 MHz~30 MHz – 1 GHz and above
Typical causeSwitching-regulator ripple on the supplyFast clock edges; cables acting as antennas
Typical fixInput filters, ferrites, decouplingShielding, ground planes, short return paths, slower edges

Practical mitigation

  1. Separate cables: keep signal cables away from motor and VFD cables; cross at 90°, never run them in parallel in the same duct.
  2. Twisted pairs and shields: twisting cancels magnetic coupling; shields block electric fields. Terminate the shield 360° at the connector for high frequencies; for low-frequency analog signals, often at one end only to avoid ground loops.
  3. Filter at the boundary: filters, ferrites and TVS diodes where cables enter the box or board.
  4. Solid ground plane and short return paths on the PCB (1.6).
  5. Suppress at the source: flyback diodes on coils, RC snubbers on contacts, output filters on VFDs.
  6. Isolate with optocouplers and isolated DC-DC converters to break ground loops (2.1).

lab1_alarm_node.ino
const int FLAME_PIN = 3;       // module DO: LOW when flame seen (check yours)
const int IR_PIN    = 4;       // module DO: LOW when obstacle seen
const int ALARM_OUT = 7;       // HIGH = healthy, LOW = alarm (fail-safe)
const uint32_t DEBOUNCE_MS = 50;

volatile uint32_t flameEdgeMs = 0, irEdgeMs = 0;
bool flame = false, obstacle = false;

// Keep ISRs tiny: record when the edge happened, nothing else.
void IRAM_ATTR onFlame() { flameEdgeMs = millis(); }
void IRAM_ATTR onIR()    { irEdgeMs    = millis(); }

void setup() {
  Serial.begin(115200);
  pinMode(FLAME_PIN, INPUT_PULLUP);
  pinMode(IR_PIN, INPUT_PULLUP);
  pinMode(ALARM_OUT, OUTPUT);
  flame    = (digitalRead(FLAME_PIN) == LOW);
  obstacle = (digitalRead(IR_PIN) == LOW);
  attachInterrupt(digitalPinToInterrupt(FLAME_PIN), onFlame, CHANGE);
  attachInterrupt(digitalPinToInterrupt(IR_PIN), onIR, CHANGE);
}

void loop() {
  uint32_t now = millis();

  // Accept a change only after the pin has been quiet for DEBOUNCE_MS
  if (flameEdgeMs && now - flameEdgeMs >= DEBOUNCE_MS) {
    flameEdgeMs = 0;
    flame = (digitalRead(FLAME_PIN) == LOW);
    Serial.printf("Flame: %s\n", flame ? "DETECTED" : "clear");
  }
  if (irEdgeMs && now - irEdgeMs >= DEBOUNCE_MS) {
    irEdgeMs = 0;
    obstacle = (digitalRead(IR_PIN) == LOW);
    Serial.printf("IR: %s\n", obstacle ? "OBSTACLE" : "clear");
  }

  // Fail-safe: energised when healthy, de-energised on any alarm
  digitalWrite(ALARM_OUT, (!flame && !obstacle) ? HIGH : LOW);
}
Tips for the Super Mini
  • No Serial output? In the Arduino IDE, set Tools → USB CDC On Boot → Enabled. The board uses the chip's native USB.
  • Upload fails? Hold BOOT, tap RESET, release BOOT, then upload again.
  • Check your module's active level with the Serial Monitor first; some modules output HIGH when triggered.
  • Adjust the module's potentiometer so it triggers reliably without chattering.
